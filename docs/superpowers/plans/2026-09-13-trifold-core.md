# Trifold Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first playable Trifold core as a clean Phaser/TypeScript project: Shenzhen-style rules, Cascade-equivalent card feel/audio, transactional Undo, deterministic deals, verified-deal production boundary, and first-class desktop/mobile-landscape HiDPI rendering.

**Architecture:** Create a new minimal Vite + Phaser + TypeScript app rather than deleting features from Cascade. Keep `src/game/model/**` free of Phaser; model commands commit an ordered operation list, then `TrifoldBoardView` animates that list using the carried-over Cascade timing/motion helpers. The runtime accepts explicit unverified seeds only in development; production New Deal can select only from a version-matched `VerifiedDealCatalog` and has no random fallback.

**Tech Stack:** TypeScript 5.9+, Phaser 3.90, Vite 7, Node built-in test runner, pnpm, DOM `ResizeObserver`.

**Spec:** `docs/superpowers/specs/2026-09-13-trifold-core-design.md`

## Global Constraints

- Product name is `Trifold`.
- Target platform is Yandex Games, but Yandex SDK/product shell work is outside this core milestone.
- Mobile gameplay is landscape-only.
- The authoritative game model must not import Phaser or depend on pixels, tweens, audio, DOM, or renderer state.
- Initial board is exactly 40 face-up cards in eight tableau columns of five cards.
- Tableau numeric runs descend by exactly one rank and every adjacent card must use a different numeric suit; empty tableau columns accept any single exposed card or any valid numeric run.
- Dragons and the flower never participate in numeric runs; either may be moved singly to an empty tableau column or empty normal free cell when exposed.
- There are exactly three free cells. A completed dragon family permanently occupies one free-cell position for the deal.
- Dragon collection requires all four dragons of that family to be exposed (tableau top or normal free cell) **and** at least one currently empty normal free cell. Collection is player-triggered only.
- Flower auto-clears whenever it is exposed.
- A numeric card auto-clears only when it is legally next on its suit foundation and no lower-ranked numeric card remains in play; equivalently every suit foundation has already reached at least `candidate.rank - 1`.
- One Undo reverses one player transaction including every auto move caused by that action.
- Player card motion is 110 ms; Undo is 110 ms; initial deal flight is 260 ms; deal stagger is 52 ms; automatic foundation/flower flight is 350 ms; easing is `Phaser.Math.Easing.Cubic.Out`/`Cubic.easeOut` equivalent.
- Reuse SFX cue semantics and file paths for `card-touch`, `card-place`, `deal`, `undo`, `button`, and `victory`; missing audio assets must not prevent model tests or startup during development.
- Preserve the Cascade HiDPI plan: `renderScale = clamp(devicePixelRatio, 1, 2)`, backing canvas = logical size × render scale, `Phaser.Scale.NONE`, inverse scale zoom, camera zoom 1, antialias on, pixel-art off, round-pixels off.
- Resize wiring uses both `ResizeObserver` and `window.resize`; abrupt resize/orientation changes must relayout cards, slots, hit/drop geometry, controls, and animation origin.
- Production deals must come from a solver-verified deterministic catalog. Runtime must never fall back to an unverified random seed when that catalog is missing or invalid.
- The actual offline solver/proof generator is a separate implementation plan after the playable core. This plan freezes the shuffle/rules/catalog contract it will consume.

- [ ] **Step 6: Implement a cross-language-friendly uint32 PRNG**

Use a non-zero xorshift32 state so C++ tooling can reproduce it exactly:

```ts
export class SeededRandom {
  private state: number;

  constructor(seed: number) {
    if (!Number.isSafeInteger(seed) || seed < 1 || seed > 0xffff_ffff) {
      throw new RangeError('Deal seed must be a positive uint32.');
    }
    this.state = seed >>> 0;
  }

  nextUint32(): number {
    let x = this.state >>> 0;
    x ^= (x << 13) >>> 0;
    x ^= x >>> 17;
    x ^= (x << 5) >>> 0;
    this.state = x >>> 0;
    return this.state;
  }

  nextInt(exclusiveMaximum: number): number {
    if (!Number.isSafeInteger(exclusiveMaximum) || exclusiveMaximum <= 0) {
      throw new RangeError('Random upper bound must be a positive safe integer.');
    }
    return this.nextUint32() % exclusiveMaximum;
  }
}
```
